# Quote-quality preflight (v4) — evidence and recommendation

**Nothing was filtered, rebuilt, modified or overwritten.** No `.h5`, `.parquet` or
`.csv` under `wrds_data_2020-2025/` was touched; no model was loaded; no training ran.
This document and `results/quote_quality_v4.{json,csv}` are counts only. The filter
decision is for a human.

Generated by `analysis/quote_quality.py --dataset-version v4` (CPU, read-only) over the
**full** v4 dataset — call 4,955,592 rows, put 7,991,054 rows, all three splits. **No
subsampling anywhere** in the reported numbers. The script carries an `assert`-based
`--self-check` for the bound arithmetic (band edges, put–call parity, the
`relative_spread → 2 as bid → 0` limit); it runs automatically before every analysis.

Split boundaries (from `VALIDATION_v4.json`): train `2015-02-02 … 2023-07-17`,
val `2023-07-18 … 2024-08-06`, test `2024-08-07 … 2025-08-29`.

### Isolated or a cluster? — **both**

The top-20 by depth (full records in `quote_quality_v4.json`) splits into two
qualitatively different families:

* **One-sided collapse** — bid at or near 0 against a four-figure ask, relative spread
  ≈ 2.0. e.g. 2022-12-12 C200 (depth 9.03), 2024-04-17 `C2200000` (bid 0.00 / ask 3069.20,
  depth 0.632), the two rows from the brief.
* **Tight two-sided quotes that are still below intrinsic** — e.g. 2022-01-25
  `SPX 261218C200000`, bid **3802.50** / ask **3994.50**, relative spread **0.049**,
  depth 0.671; 2020-12-30 `SPX 231215C100000`, bid 3436.90 / ask 3461.50, relative
  spread **0.007**, depth 0.597. These are *stale but two-sided* deep-ITM LEAPS. **No
  spread- or bid-based rule can see them.**

Every one of the top 20, in both families, has `impl_volatility = NULL`.

The tail is not two rows. Across the full dataset there are 109,323 call and 65,705 put
lower-bound violations; 4,158 call rows exceed depth 0.01 and 2 exceed depth 1.0.

Pairwise overlaps (call / put):

| pair | call | put |
|---|---:|---:|
| bid≤0 ∩ rs>1 | **109,954 (= all of bid≤0)** | **122,452 (= all of bid≤0)** |
| IV NaN ∩ out-of-bounds | **107,797 (98.6% of violations)** | **64,216 (97.7%)** |
| rs>1 ∩ out-of-bounds | **16** | **15** |
| bid≤0 ∩ out-of-bounds | 7 | 13 |
| bid≤0 ∩ IV NaN | 1,225 | 627 |
| crossed ∩ anything | 0 | 0 |

Three facts drive the recommendation:

1. **`best_bid <= 0` is exactly a subset of `rel. spread > 1`** — as bid → 0,
   `(ask−bid)/mid → 2`. Adding the bid rule on top of a spread rule with threshold ≤ 2
   removes literally zero extra rows. It also explains why **rel. spread > 2 and > 5
   remove nothing at all**: with `best_bid ≥ 0` the ratio is bounded above by 2, so any
   threshold above 2 can only fire on crossed quotes, of which there are 14 (call) and
   17 (put) in ~13M rows.
2. **The spread rules and the bound rule are almost disjoint** — `rs>1 ∩ out-of-bounds`
   is **16 rows out of 109,323** for calls. A spread filter, at any threshold, does **not**
   fix the static-bound problem. That is the tight-two-sided-stale-LEAPS family from §1.
3. **`impl_volatility` NaN is a ~98% proxy for the bound violations** — but this is
   **corroborating, not independent, evidence**: OptionMetrics' inversion returns NULL
   *precisely because* it fails on the same inconsistent midpoint and carry inputs the bound
   arithmetic flags, so the two signals share a root cause rather than being two separate
   witnesses. It is a useful sanity check that the rule tracks something the vendor's own
   pipeline also chokes on, but it should not be read as a second, independent line of
   evidence, and it should not be the rule itself (vendor artifact).

## 3. Recommendation

> **Drop any quote whose midpoint `(best_bid + best_offer)/2` divided by the strike lies
> outside the static no-arbitrage band — calls outside `[max(M·e^{−qT} − e^{−rT}, 0),
> M·e^{−qT}]`, puts outside `[max(e^{−rT} − M·e^{−qT}, 0), e^{−rT}]`.**

One sentence, fully deterministic, no tuned constant, no threshold to defend.

**Why this one.** It is computed entirely from observables already in the file
(`best_bid`, `best_offer`, `strike`, `moneyness`, `T`, `r`, `q`) plus textbook arithmetic —
no vendor judgement call, unlike the `impl_volatility`-NULL rule, which nonetheless agrees
with it on 98.6% of rows — a corroborating, not independent, signal (see §2.3: the vendor's
own inversion fails for the same underlying reason, so this is the same evidence seen twice,
not two witnesses). Crucially it is the only candidate that removes rows whose midpoints are
**inconsistent with the static no-arbitrage bounds under the supplied spot, rate,
dividend-yield, and settlement inputs**: a price below intrinsic under those inputs cannot be
produced by the Black–Scholes decoder at *any* σ̂, so these rows are pure irreducible error
that caps attainable R² exactly the way the old `T=0` rows did — the filter deletes only what
the model could never fit given the inputs it is given, which is the cleanest possible
justification in a manuscript. (This is a claim about internal consistency of the supplied
inputs, not a claim that a riskless market arbitrage existed — `r`, `q`, and the settlement
timestamp are themselves estimates, not observed riskless trades.) Spread-based rules fail
the task: they miss 109,307 of the 109,323 call violations, including every tight-two-sided
stale LEAPS, while deleting 79,834 rows nothing else flags.

**Honest caveat — the removal is systematically concentrated, and this must be disclosed.**
The rule is not uniform: it takes ~34% of the deep-ITM call bucket (`M>1.2`) and ~39% of
the deep-OTM put bucket (`M<0.8`), and ~11.6% of the 2–7-day call bucket. Those buckets
are, however, small in absolute terms — `M>1.2` is 2.06% of all calls (102,286 rows) and
`M<0.8` is 0.30% of all puts (24,305 rows) — so the effect on the overall sample is the
~2.2% / ~0.8% above. The largest absolute contributors are actually the moderately-ITM
call bucket `1.05–1.2` (42,384 rows) and near-ATM calls (32,065 rows). A paper using this
filter should state the deep-ITM/short-dated concentration explicitly rather than report
only the headline percentage.

### Train-vs-test differential — acceptable for this rule, disqualifying for the alternatives

For the recommended rule the differential is small: **call test 2.516% vs train 1.878%
(+0.64 pp)**, **put test 0.726% vs train 0.881% (−0.16 pp)**. Removal rates are within a
factor of ~1.3 across splits, so the evaluation distribution barely moves.

**This is the main reason to reject the spread-based rules.** `rel. spread > 1` removes
**4.501% of train but only 2.326% of test** for calls (−2.18 pp; ~1.9× more of train), and
**3.218% vs 1.163%** for puts (−2.06 pp; ~2.8×). `best_bid <= 0` is worse still: 2.776%
train vs 0.634% test for calls, a **4.4× ratio**. This is a genuine secular trend — the
train window is 2015-02 → 2023-07 and the test window 2024-08 → 2025-08, over which SPX
quoting tightened substantially — but the consequence is the same either way: a spread
filter would strip proportionally far more of the training sample than of the evaluation
sample, systematically shifting the train/test distributions apart and making the reported
test metrics non-comparable to the pre-filter numbers. The bound rule does not do this.
`impl_volatility` NaN is also acceptable on this axis (call +0.53 pp, put −0.13 pp) and is
the natural robustness check to report alongside the recommendation.

**Reading the tolerance sweep.** A tolerance of `1e-3` cuts the removal by ~5× (call
0.437%, put 0.100%) while still eliminating every pathological row — the 6.49 / 6.33 /
9.03-depth artifacts survive any tolerance below ~6. If a reviewer objects to deleting
2.2% of calls, `tol = 1e-3` is the natural fallback: it keeps the marginal violations
(median depth ~4e-4, plausibly just interpolation noise in `r`, `q` and the spot
timestamp) and drops only the economically meaningless ones. The cost is a magic constant
in the manuscript sentence, which is why tol = 0 is the primary recommendation.

## 5. Reproduce

```bash
conda run -n dl_new python analysis/quote_quality.py --dataset-version v4 --self-check
conda run -n dl_new python analysis/quote_quality.py --dataset-version v4
```

Outputs `results/quote_quality_v4.json` (rule stats, incremental/pairwise overlaps, full
top-20 records with raw-CSV traces) and `results/quote_quality_v4.csv` (flat
rule × split × dimension × bucket table). `--max-contracts N` subsamples for iteration and
sets `"subsampled": true` in the JSON; the numbers above have `"subsampled": false`.
`--no-trace-raw` skips the 8.6 GB CSV scan.

**Again: this was analysis only. No filter was applied and no dataset was rebuilt.**
